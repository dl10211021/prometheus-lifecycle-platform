# Prometheus 成对恢复事务日志（第 10.2.2.2 步）

本步提供内部事务准备与安全撤销，为后续实际恢复建立持久化隔离。准备会重新执行已有的完整恢复准入预览，随后保存绑定证据；不会停止、启动或重载服务，也不会替换二进制、启动文件、配置或 TSDB。

## 内部接口与状态

- `BackupService.PreparePrometheusPairedRestoreTransaction(ctx, planID)`：按主机锁、组件锁的顺序获取所有权，核验历史与当前状态，在同一 SQLite 事务内复查数据库身份和锁，再创建 `prepared / revision 1`。
- `BackupService.AbortPreparedPrometheusPairedRestoreTransaction(ctx, transactionID)`：重新核验可信身份，以条件更新将唯一一行改为 `aborted / revision 2`。撤销只访问数据库；重复撤销有效的已结束事务不会再次修改时间或历史。
- `PrometheusRestoreTransaction` 保留计划、恢复点、备份、组件、主机、状态和时间。私有证据包含版本、绑定摘要、历史摘要及预览时间；随机令牌、证据载荷和活动唯一键不出现在公共 JSON 中。原始命令参数、环境内容和 SSH 凭据不进入日志载荷。
- 活动主机键和组件键分别唯一。撤销同时清空两者，保留历史行，允许之后创建新的事务。
- 未实现任何后续阶段。未来执行第一次主机修改前，必须先持久化离开 `prepared`；未知阶段不能使用本步撤销接口。

当前没有 HTTP 入口，也没有接入自动升级或自动回滚。实际文件替换、当前停止态检查点、失败补偿和恢复执行阶段仍属下一步。

## 并发与失败

待处理日志会隔离所属主机、同机已登记组件以及原组件（即使它后来迁移到其他主机）。其他主机在正常运行期间仍可独立操作。

通用主机/组件声明在获取前、重入返回前和新声明写入后检查日志。准备提交时再次检查自身两个令牌仍在数据库，并拒绝同机其他组件的未结束操作。这样覆盖了“检查之后才出现日志”和“声明已经先写入”的两种顺序。

只有安全撤销生成的私有上下文能够越过其绑定日志，且必须同时匹配事务、令牌、主机和组件。它不能绕过其他日志、备份暂停或版本转换屏障；操作类型字符串不能授予权限。

写入失败、零行更新、SQLite 提交失败、取消、锁丢失、身份漂移、损坏数据及未知阶段都不能由本接口清除活动隔离。待处理清单最多 1024 行，单条载荷最多 64 KiB；读取失败或超限均拒绝操作。旧数据库尚无日志表时兼容原流程，实际服务器启动会迁移该表。

## 崩溃与服务器启动

服务器先取得实际数据库的操作系统独占进程锁，再处理以下流程，期间不派发业务工作。

1. 若整库恢复状态为 `applying`，保留的 `.restore-original` 是初始化完成前的权威原库。先验证其文件、SQLite 完整性和完整待处理日志清单，再调用已有整库回滚。候选数据库的旧日志或损坏内容不能阻止恢复一个已验证的原库；缺失或损坏的原库则会阻止替换。有效待处理日志可以随原库回到当前数据库，并继续受到隔离。
2. 读取当前数据库时包含 WAL，不能使用会忽略最新 WAL 内容的 `immutable=1`。普通只读检查不会创建缺失的数据库，也不修改业务数据。
3. 如果所有待处理日志都有效且处于 `prepared`，仅在上述独占进程锁保护下，用一个事务清理关联主机、原组件及同机组件遗留的临时操作声明。提交日志后、释放声明前崩溃，以及同机声明写入后、再次检查前崩溃，均能据此处理。无关主机的声明和业务行保持不变；损坏或未知日志不允许清理。
4. 清理临时声明后仍拒绝正常启动，保留日志和待恢复快照。不会自动撤销，也不会调用通用配置/数据恢复来处理成对恢复事务。
5. 模式迁移后、业务元数据迁移前还有检查，防止从快照导入的待处理事务在检查前被重绑定。通用组件恢复入口也独立检查日志。

显式解决 `prepared` 日志使用上述内部撤销方法。运行期间的撤销不会抢占仍可能属于活动进程的声明；崩溃遗留声明由受独占进程锁保护的服务器启动流程定向处理。后续产品入口需在这些约束上接入，不应通过删除日志或修改阶段解决隔离。

## 验证范围

回归覆盖新旧数据库迁移、WAL、整库恢复中断、真实子进程退出、声明重入与并发窗口、独立唯一键、记录/令牌变化、历史和主机漂移、暂停屏障、容量与格式边界、取消、写入/提交失败和清理的原子性。

真实主机验收沿用显式独占的 Prometheus 2.55.0 夹具，通过 `PROMLIFECYCLE_PAIRED_RESTORE_JOURNAL=1` 开启。准备、隔离、全新服务对象的撤销前后比较 PID、启动文件和固定时间点 TSDB 样本，并检查历史元数据不变、声明释放及夹具清理。WSL 中不受支持的非绝对路径 systemd 引用应在写入意图前被拒绝。
